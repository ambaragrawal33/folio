# Owned Asset Detail contract

Priority4,2026-10-06. `GET /api/v1/portfolios/:portfolioId/instruments/:instrumentId/detail` requires a verified session and server-owned portfolio. Strict `page/pageSize/lotPage/lotPageSize` query, default20/max100 items per collection, pages1–10000. Existing Redis GET bucket and no-store apply. Unknown/unowned resources use the same404 envelope; malformed query400; unauthenticated401. Instrument ID is canonical and bounded to100 characters; raw/unknown symbols do not resolve implicitly.

Response: `instrument`, `portfolioId`, economic `revision`, `baseCurrency`, nullable `position` and `holding` summaries (full lot arrays omitted), current `valuation` coverage/status/as-of, `lots` page and `activity` page. No other user's or unrelated instrument economics/lots, account fields, portfolio holdings or aggregate money totals are returned. Portfolio coverage is needed to explain unavailable weight even when the selected asset has a valid price.

Lot fields reuse server `transactionId`, remaining `quantity`, `localCost`, `baseCost`; `acquisition` is the original immutable BUY from the same owned ledger snapshot with effective UTC instant, exchange date, quantity/unit price, fees and historical FX rate/date/source/reference. FIFO order and costs come from existing replay. Partial sells consume oldest units/cost; splits adjust current units while preserving lot cost, without modifying original acquisition fields. No client FIFO/per-unit financial recomputation.

Activity uses existing `LedgerRow`: original `record`, original signed `nativeCashFlow` and nullable immutable `void` metadata (ID, transaction ID, reason, recorded timestamp). Descending effective instant/sequence, exact instrument filter before paging. Voided economics stay visible with their original amounts; they are excluded from replay, not physically deleted. BUY/SELL/DIVIDEND/SPLIT amounts and recorded FX/date provenance are retained. Current quantity0 after a full sale can retain realized P&L/income and no lots. A known canonical instrument without an economic position returns null position/holding, empty lots and only the caller's activity, including void-only records.

Read-only Mongo snapshot of portfolio/economics/voids, one batch canonical metadata read, one existing replay and one quote/FX gateway batch for active owned instruments. Four fixed domain reads; no per-lot/acquisition/void lookup or per-row HTTP call. Record/void maps join in memory within the existing10,000-economics bound. Provider observations occur after the consistent economic read; no upstream lock claim. Internal gateway batches can make bounded provider/cache calls according to existing capabilities; no claim of one upstream call across all instruments. No financial/domain mutation or booking audit by this GET.

The UI uses one detail request plus the existing separate permitted price-history request. History is reused for60 seconds across lot/activity navigation; the application's existing30-second detail-cache policy remains. Existing writes invalidate domain queries. No Priority5 polling/job/recovery infrastructure is introduced. Explicit malformed/error recovery retains safe product copy and a path back to holdings.

Complete/stale/partial/missing valuation uses existing server semantics. Missing price/FX yields null value/P&L, never zero; partial coverage keeps weight unavailable. Quote/current FX source/date/status and synthetic fixture labels remain visible. No new prices, historical backfill, provider activation/entitlement, tax, TWR, historical portfolio snapshots or automatic corporate actions.
