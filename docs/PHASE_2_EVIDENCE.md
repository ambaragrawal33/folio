## Meaningful verification and limits

Auth integration runs actual Mongo transactions in random isolated databases; fixtures are explicit tests, not production defaults. It verifies hashed/secret-free storage and responses, generic duplicate/email responses, no password overwrite, purpose separation, single-use/expiry, revoked/reused/concurrent refresh, immediate JWT revocation, expired access/family, logout idempotency, password reset/change, progressive lockout, CSRF/origin/strict NoSQL rejection, duplicate cookies/tampering, Secure production-cookie policy, unavailable SMTP auditing and fail-closed limits. Two-account read/update/export/delete tests prove server-bound identity and ensure the other account survives. Deletion/export must grow when future owned collections ship.

Browser E2E registers an actual account, retrieves real MailHog links, explicitly verifies and logs in, restores/rotates sessions on reload, saves/reloads preferences, downloads JSON/CSV and confirms deletion. A second flow proves reset/change/logout/protected-route behavior. It verifies memory-only credential storage, httpOnly/SameSite cookie policy, invalid-link/expired/offline states, label/focus behavior, Figma card/field/submit geometry, Dark/Light axe and 390px overflow. Both-theme Settings captures are 1440×1024; Light/mobile layouts and missing states are derived and provisional for user review.

Overall coverage thresholds are 70% for lines/statements/functions/branches; [actual summary](evidence/phase-2/coverage-summary.json) is retained. Financial-core 90% gate is configured and explicitly N/A because this phase implements no financial engine. SMTP production delivery and real HTTPS/Safari are not covered by local test fixtures or inferred from Chrome.
