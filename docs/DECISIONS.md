## Confirmed instructions and actions

Phase 2 implementation refinements (within the authorized P0 scope): password minimum 12 / maximum 128 characters; 256-bit random purpose-bound action/refresh tokens hashed with a stable server HMAC key. Action tokens travel in URL fragments and require an explicit verify/reset action. User-facing email responses are generic even on unavailable SMTP; failures are recorded as delivery_failed. Runtime configuration uses generated development keys unless ignored .env persists them; production startup remains forbidden until deployment/provider choices exist. Production cookie policy is Secure/httpOnly/SameSite=Strict, with the documented loopback HTTP exception; no production key is requested.

All cookie-changing auth requests share the refresh session queue and Navigator Lock. This prevents login/logout/reset/change/delete from racing the initial refresh; a delayed-refresh/login regression test verifies the ordering. Protected account identity is displayed only while authenticated, so expired/anonymous screens cannot show stale query identity. These are auth correctness fixes, not visual redesigns.

Profile changes allow only name, IANA timezone and approved theme/number format. Verified email/role/INR defaults cannot be rewritten by request fields. Saved theme takes effect at session restoration unless an explicit review theme query is present. User identity is server-bound; future domain ownership must extend this pattern. Export includes public account/audit data in JSON/CSV, formula-protects cells and excludes credentials. Deletion requires current password and DELETE and removes owned auth/audit data transactionally; only an identity/IP/browser-free deletion event remains. Future domain models must register cascade/export before shipping.

Node's strip-only development runner requires erasable TypeScript; the API compiler now enforces erasableSyntaxOnly to catch incompatible parameter properties before runtime. No transform runtime/dependency was added. Mongo test preparation is explicit because Windows download time exceeded the bounded test setup hook; this changes provisioning, not test coverage or security behavior. CI starts the real stack before auth E2E and uses immutable user-approved Phase 1 captures with at most 0.5% platform-rendering pixel tolerance. New auth/account captures remain provisional for user review; Light/mobile are derived, never Figma-approved.
